# PointerWhy
Paste a JSON document and an RFC 6901 JSON Pointer: the selected value, or the step where it fails and why; both string and URI-fragment forms. Static client-side app, open `app.html`.
Source: https://www.rfc-editor.org/rfc/rfc6901.txt (fetched in full, 11 KB). RFC 3986 (fragment syntax) was not fetched; the rule that a "%" must be followed by two hex digits is my reading of it.
Tests: `node test-rfc.js` runs every example from RFC 6901 sections 5 and 6 in both forms (string and fragment), the ~01 / ~10 decoding-order cases, and compares the built-in JSON parser with JSON.parse on a corpus. `oracle.py <seed> <n> <out.jsonl>` generates random documents and pointers (valid walks plus mutations: leading zeros, "-", out of range, case changes, joined slashes, bad escapes, missing "#", bad percent-escapes) and resolves them with the Python jsonpointer package 3.1.1; `node test-engine.js *.jsonl` compares. 128,000 cases (seeds 1 to 5, all run after the code was final): 125,917 compared, 0 differences, 79,320 of them resolving to a value. The other 2,083 are cases where jsonpointer steps into a string character (it returns "b" for /a/0 on {"a":"bar"}); RFC 6901 section 4 allows stepping only into objects and arrays, so these were excluded and the engine reports an error. Also a 60,000-case mutation fuzz of the JSON parser against JSON.parse (0 differences; the fuzz harness was inline and is not in the repo).
Not independently checked: the fragment-form oracle uses Python's percent-decoding plus my own rule for malformed "%" sequences; step explanations and hints are not checked by any tool.
